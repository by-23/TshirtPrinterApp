# План реализации — Приложение для принта на футболках

> Составлен на основе ТЗ «Приложение для принта» и результатов гриллинга (архитектурные решения зафиксированы ниже).

## Принятые архитектурные решения

| Решение | Выбор |
|---|---|
| Развёртывание | Локальный сервер на каждой точке (мини-ПК) |
| Центральный сервис | Тонкий облачный relay для QR-загрузки, админки и статистики |
| QR-загрузка фото | Режим relay (через центр) **и** режим own-WiFi — переключатель в админке |
| Поведение при потере интернета | Работать по последнему кэшу (fail-open); ИИ-стилизация недоступна без интернета |
| ИИ | Бесплатные решения через интернет; вырезание фона — в браузере, стилизация — Pollinations API |
| Стек | TypeScript fullstack (Node.js + React) |
| Цены | Глобальный прайс + переопределение для конкретной точки |

---

## 1. Стек технологий

**Единый язык — TypeScript** (везде: клиент, точка-сервер, центральный сервер).

| Слой | Технологии | Зачем |
|---|---|---|
| Frontend (киоск + оператор + админка) | React 18 + TypeScript + Vite, TailwindCSS, React Router, Zustand | быстрый touch-friendly UI, единая кодовая база под разные экраны |
| Мультиязычность | react-i18next | готовая i18n, легко добавить RU/KK/EN/ZH |
| Карусель баннера | Swiper.js | автоскролл + свайп из коробки, лицензия MIT |
| Редактор дизайна | Fabric.js | готовый canvas-движок: drag/scale/rotate/flip/текст/стикеры/слои |
| Realtime (заказы у оператора, статус точки) | Socket.IO | WebSocket с автопереподключением, работает и для outbound-соединения точки к центру |
| Удаление фона (ИИ-раздел) | `@imgly/background-removal` | работает **прямо в браузере** (WASM/ONNX), бесплатно, без сервера и лимитов, кэшируется — переживает офлайн |
| Стилизация фото (ГТА/аниме/нуар) | Pollinations.ai API (image-to-image, модели `kontext`/`gptimage`/`nanobanana`) | бесплатный публичный API, есть image-to-image по референс-фото, бесплатная регистрация снимает часть лимитов |
| QR-коды | `qrcode` (сервер) / `qrcode.react` (клиент) | генерация QR на лету |
| Backend точки (point-server) | Node.js + TypeScript + Fastify | лёгкий, быстрый, отличная типизация |
| БД точки | SQLite (`better-sqlite3`) + Drizzle ORM | zero-config, один файл, не нужен отдельный сервис на мини-ПК |
| Композитинг изображений (мокап + чистый дизайн → PNG) | `sharp` | быстрый, готовый, не нужен canvas на сервере |
| Backend центра (central-relay + админка) | Node.js + TypeScript + Fastify, PostgreSQL + Drizzle ORM | тот же ORM что и на точке, единый язык запросов |
| Auth админки | JWT + bcrypt | стандартная связка |
| UI админки | Ant Design (antd) + Recharts | готовые таблицы/формы/графики — не рисуем админку с нуля |
| Загрузка файлов (QR-relay, видео-реклама) | Fastify `@fastify/multipart` | стандартный плагин |
| Монорепозиторий | pnpm workspaces + Turborepo | общий код (типы, i18n, pricing-логика) между всеми приложениями |

Всё — готовые open-source библиотеки, кастомного пишем по минимуму (в основном бизнес-логику: цены, синхронизацию, композитинг заказа).

## 2. Архитектура

**Точка = локальный сервер** (мини-ПК гонит оба монитора и хранит всё локально).  
**Central-relay** — тонкий облачный сервис для:
- админки (открытие/закрытие точек, статистика);
- приёма фото по QR с телефона клиента;
- доставки обновлений каталога на все точки.

```
                         ЦЕНТРАЛЬНЫЙ ОБЛАЧНЫЙ СЕРВЕР (central-relay)
                         - Postgres: точки, админы, сводная статистика,
                           мастер-каталог (дизайны/категории/ИИ-стили/реклама)
                         - Admin Panel (Ant Design)
                         - QR-upload relay endpoint (для режима "через интернет")
                                   ▲                              ▲
                       outbound WebSocket (точка сама             HTTPS (клиент грузит
                       инициирует, работает без белого IP)        фото по QR с телефона)
                                   │                              │
        ┌──────────────────────────────────────────────────────────────────┐
        │                    ТОЧКА (мини-ПК, локальный сервер)               │
        │  point-server (Fastify) + SQLite + локальные PNG/MP4              │
        │   - хранит: заказы, каталог (кэш), цены, операторов, рекламу      │
        │   - работает офлайн по последнему известному состоянию            │
        │   - режим QR: relay (через центр) ИЛИ own-WiFi (точка раздаёт AP) │
        │              │                              │                     │
        │      Chrome kiosk (монитор 65", клиент)   Chrome (монитор оператора)
        │      localhost:PORT/kiosk                  localhost:PORT/operator│
        └──────────────────────────────────────────────────────────────────┘
```

### Почему так

- **local_server** — вся логика заказа, редактор, печать работают на точке без интернета.
- **fail_open_cache** — точка держит закэшированный статус «открыта/закрыта» и цены, синкается когда есть связь.
- **QR: relay + same_wifi** — переключатель `point.upload_mode: 'relay' | 'wifi'` в админке.
- **AI бесплатно** — вырезание фона в браузере, стилизация через Pollinations.
- **Цены** — global + override на точку.

## 4. Ключевые сущности данных

### point-server (SQLite, на точке)

- `point_config`
- `operators`
- `categories`
- `designs`
- `banner_items`
- `ai_styles`
- `garments` (тип/цвет/размер/ткань)
- `print_size_prices` (маленький/средний/большой)
- `ads_videos`
- `orders` (статус: new → accepted → printing → done, пути к 2 PNG)
- `sync_queue` (очередь для отправки в центр при восстановлении связи)

### central-relay (Postgres, в облаке)

- `points` (имя, логин/пароль оператора, статус open/closed, upload_mode)
- `admins`
- `catalog_master` (дизайны/категории/ИИ-стили/реклама — эталон, точки синкают вниз)
- `orders_archive` (агрегация для статистики)
- `upload_sessions` (токен QR-сессии, привязка к точке, TTL)

## 5. Функциональные модули (из ТЗ)

### Основное приложение (киоск)

- Выбор языка: RU / KK / EN / ZH
- Автоскролл-баннер (популярные, новинки — управляется из админки)
- Разделы: Мемы, Аниме и Фильмы, Игры, Надписи, Свой дизайн, ИИ-стиль
- Редактор: тип одежды, сторона, цвет/размер/ткань, масштаб/поворот/отзеркалить, текст, стикеры, загрузка фото
- Расчёт цены по типу одежды, ткани, размеру и размеру принта (S/M/L)
- Экран «Печать» → «Оплатите в кассу» → подтверждение оператором → «Заказ принят, ждите 5 мин» (15–20 сек)
- Реклама при бездействии (случайные mp4 из базы)

### Окно оператора

- Лента заказов в реальном времени
- Кнопка «Принять заказ»
- 2 PNG на заказ: мокап на футболке + чистый дизайн
- Скачивание для ручной печати
- Учёт заказов

### Админка

- Статистика продаж и заказов
- Управление каталогом, баннерами, рекламой, ИИ-стилями
- Открытие/закрытие точек (логин/пароль оператора)
- Настройка цен (глобально + override на точку)
- Переключение режима QR-загрузки (relay / wifi)

## 6. Пошаговый план реализации

### Этап 0 — Скелет проекта (1 спринт)

- Инициализация monorepo (pnpm + Turborepo)
- Общие пакеты: `shared-types`, `i18n`, `ui-kit`
- ESLint / Prettier / TS-конфиги, CI (lint + build)
- Пустой `point-server` (Fastify + SQLite + Drizzle миграции)
- Пустой kiosk-app (Vite + React), связка с point-server

### Этап 1 — Каркас киоска: навигация, язык, баннер

- Главная страница
- Переключатель языка (react-i18next)
- Автоскролл-баннер (Swiper)
- Переходы в разделы (пока заглушки)

### Этап 2 — Редактор дизайна (ядро)

- Интеграция Fabric.js
- Выбор толстовка/футболка, сторона (перед/зад), цвет/размер/ткань
- Инструменты: масштаб, поворот, отзеркалить, текст, шрифты, цвета, стикеры, загрузка фото
- Рендер мокапа (наложение дизайна на превью одежды)

### Этап 3 — Разделы каталога

- Мемы / Аниме и Фильмы / Игры — общий грид-галерея → редактор с preset-дизайном
- Надписи / Свой дизайн — чистая одежда + полный редактор
- CRUD каталога в point-server (позже — управление из админки)

### Этап 4 — Расчёт цены и оформление

- `shared-pricing`: цена = f(тип одежды, ткань, размер, размер принта S/M/L)
- Экран «Печать» → «Оплатите в кассу»
- Ожидание подтверждения оператором
- Плашка «Заказ принят, ждите 5 мин» (автоскрытие 15–20 сек)

### Этап 5 — Окно оператора

- Роут `/operator` на point-server
- Лента заказов (Socket.IO, localhost)
- «Принять заказ» → смена статуса → событие клиенту
- Экспорт 2 PNG (мокап + чистый дизайн через `sharp`)
- Простой учёт заказов

### Этап 6 — Central-relay + админка

- Fastify + Postgres
- CRUD точек (создать/открыть/закрыть, логин-пароль)
- Мастер-каталог контента
- Сводная статистика (Ant Design + Recharts)
- Outbound WebSocket от точки к central-relay

### Этап 7 — Синхронизация точка ↔ центр

- Pull: каталог, цены, реклама, статус точки
- Push: заказы, статистика
- Офлайн-очередь с ретраями
- Fail-open: работа по последнему кэшу

### Этап 8 — Реклама при бездействии

- Таймер бездействия на киоске
- Полноэкранный плеер mp4 (случайный порядок)
- Загрузка через админку, синк на точку

### Этап 9 — ИИ-раздел

- Съёмка с камеры (`getUserMedia`) или загрузка через QR
- `upload-relay` в central-relay + режим own-wifi
- Вырезание фона: `@imgly/background-removal` в браузере
- Стилизация (ГТА/аниме/нуар): Pollinations image-to-image через point-server

### Этап 10 — Развёртывание на железе

- Windows-скрипт автозапуска point-server + Chrome kiosk на оба монитора
- `--kiosk`, разные `--user-data-dir` под клиент и оператора
- Автозапуск при загрузке ПК
- Механизм обновления точки (git pull / релиз по сигналу от central-relay)

### Этап 11 — Пилот и доводка

- Запуск на первой точке
- Обратная связь от оператора
- Донастройка цен/каталога через админку
- Проверка QR-flow и лимитов Pollinations
- Подготовка ко второй точке (весь конфиг через админку)

## 7. Допущения

- Хостинг central-relay — любой VPS/PaaS с Postgres (Railway, Render, свой VPS).
- Видео-реклама и мастер-каталог хранятся на central-relay (диск или S3) и скачиваются точкой при обновлении.
- Оператор и клиент — один React-app с разными роутами.
- Обновление point-server на первых порах — вручную/по сигналу; полноценный авто-апдейтер — после пилота.
- Оплата в приложении не реализуется на первых этапах («Оплатите в кассу»).
- Печать — вручную оператором (загрузка PNG в софт принтера).

## 8. Риски и митигация

| Риск | Митигация |
|---|---|
| Лимиты Pollinations (rate limit, watermark) | Бесплатная регистрация; fallback на другие бесплатные API; кэш результатов |
| Первый запуск `@imgly/background-removal` медленный | Предзагрузка WASM/модели при старте киоска; self-host assets |
| Потеря интернета на точке | Fail-open: каталог и заказы работают локально; sync_queue |
| QR не работает без relay | Два режима: relay + own-WiFi; переключатель в админке |
| Два монитора / два окна Chrome | Отдельные профили Chrome, kiosk-режим, автозапуск скриптом |
